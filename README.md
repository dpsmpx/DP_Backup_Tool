# DP Backup Tool

Программа сохраняет структуру каталогов и «отпечатки» файлов в JSON, а потом
раскладывает восстановленные файлы обратно по их исходным местам.

Сценарий, ради которого она написана: на носителе ломается файловая система,
вы вытаскиваете данные через TestDisk/PhotoRec и получаете кучу файлов с
потерянными именами и без структуры папок. Если структура была записана
заранее — эта программа вернёт файлы туда, где они были.

---

## Как сопоставляются файлы

Это главное отличие от версии 1.x, которая сопоставляла файлы **только по
размеру** и при совпадении размеров молча раскладывала их неправильно.

Версия 2 идёт по ярусам, от самого надёжного признака к самому слабому:

| Ярус | Признак | Надёжность |
|------|---------|-----------|
| 1 | Хеш содержимого (SHA-256) | точно; работает даже если имя потеряно |
| 2 | Размер + имя файла | высокая |
| 3 | Размер + расширение (единственное совпадение) | средняя |
| 4 | Размер, уникальный во всём источнике | средняя |
| — | Ничего из перечисленного | **файл не копируется**, попадает в отчёт |

Ключевой принцип: **при неоднозначности программа не гадает.** Такие файлы
перечисляются в отчёте, чтобы вы разобрались с ними вручную. Старое поведение
(взять первый попавшийся файл подходящего размера) доступно по явному флагу
`--allow-ambiguous`.

Дубликаты обрабатываются правильно: если в исходном дереве один и тот же файл
лежал в трёх местах, а восстановилась одна копия — она будет скопирована во все
три места.

## Установка

Нужен только Python 3.9 или новее — внешних зависимостей нет.

```bash
git clone https://github.com/dpsmpx/dp_backup_tool.git
cd dp_backup_tool
python DP_Backup_Tool.py
```

Для графического интерфейса нужен Tkinter (в Windows и macOS он идёт в
комплекте с Python; в Debian/Ubuntu: `sudo apt install python3-tk`). Без
Tkinter программа полностью работает из командной строки.

Опционально можно установить как пакет — тогда появится команда `dp-backup`:

```bash
pip install .
```

## Графический интерфейс

Запустите скрипт без аргументов (или двойным щелчком):

```bash
python DP_Backup_Tool.py
```

1. **Записать структуру** — выберите папку и файл, куда сохранить `.json`.
2. **Разложить файлы обратно** — укажите структуру, папку с восстановленными
   файлами и пустую папку назначения.

Галочка «Предварительный просмотр» включена по умолчанию: первый запуск ничего
не пишет на диск, а только показывает отчёт о том, что будет сделано.

## Командная строка

### Запись структуры

```bash
python DP_Backup_Tool.py export ПАПКА СТРУКТУРА.json [опции]
```

| Опция | Назначение |
|-------|-----------|
| `--hash full` | SHA-256 по всему файлу. По умолчанию, самый надёжный вариант |
| `--hash partial` | SHA-256 по размеру и первым/последним 64 КиБ — быстрее на больших файлах |
| `--hash none` | Без хешей: только имена и размеры (поведение версии 1.x) |
| `--follow-symlinks` | Записывать симлинки как обычные файлы, а не как ссылки |
| `--report PATH` | Сохранить отчёт в файл |

Пример:

```bash
python DP_Backup_Tool.py export /mnt/ssd/Данные structure.json
```

### Восстановление

```bash
python DP_Backup_Tool.py restore СТРУКТУРА.json ИСТОЧНИК НАЗНАЧЕНИЕ [опции]
```

| Опция | Назначение |
|-------|-----------|
| `-n`, `--dry-run` | Показать, что будет сделано, ничего не записывая |
| `--overwrite` | Заменять уже существующие файлы в папке назначения |
| `--allow-ambiguous` | Копировать «наугад» при совпадении размеров (может положить не тот файл) |
| `--verify` | Перечитать каждый скопированный файл и сверить хеш |
| `--skip-invalid` | Продолжить, если в файле структуры есть непригодные записи |
| `--no-symlinks` | Не воссоздавать символические ссылки |
| `--no-mtime` | Не восстанавливать даты изменения |
| `--report PATH` | Сохранить отчёт (`.json` — в машиночитаемом виде) |

Рекомендуемый порядок:

```bash
# 1. сначала посмотреть, что получится
python DP_Backup_Tool.py restore structure.json ./recovered ./restored --dry-run

# 2. если всё устраивает — выполнить и проверить результат
python DP_Backup_Tool.py restore structure.json ./recovered ./restored --verify
```

### Общие опции

Действуют для обеих команд и указываются перед ними:

| Опция | Назначение |
|-------|-----------|
| `--log PATH` | Писать лог в указанный файл вместо служебного каталога |
| `-v`, `--verbose` | Подробный лог (уровень debug) |
| `-q`, `--quiet` | Не печатать прогресс и отчёт, только записать их в файл |
| `--version` | Показать версию и выйти |

```bash
python DP_Backup_Tool.py --log ./run.log -q export ./Данные structure.json
```

### Коды возврата

| Код | Значение |
|-----|----------|
| 0 | Всё в порядке |
| 1 | Работа завершена, но что-то требует внимания (не найдено, неоднозначно, ошибки) |
| 2 | Запуск невозможен (неверные аргументы, нечитаемая структура) |
| 130 | Прервано через Ctrl-C |

## Отчёт

После каждого запуска выводится отчёт: сколько файлов восстановлено, что не
найдено, что оказалось неоднозначным и какие файлы сопоставлены по слабым
признакам и стоят проверки. Отдельными разделами перечисляются проблемы в файле
структуры и ошибки чтения источника.

Полный лог пишется в служебный каталог пользователя и **ротируется** (5 МиБ ×
3 файла), поэтому не может заполнить диск:

* Windows — `%LOCALAPPDATA%\DP_Backup_Tool\backup_tool.log`
* macOS — `~/Library/Logs/DP_Backup_Tool/backup_tool.log`
* Linux — `~/.local/state/dp_backup_tool/backup_tool.log`

Путь можно задать самому: `--log /куда/нужно.log`.

## Безопасность

Файл структуры — это недоверенные данные: его могли передать, отредактировать
или повредить. Поэтому:

* пути с `..`, абсолютные пути, буквы дисков и UNC отклоняются при загрузке;
* перед каждой записью путь проверяется на то, что он действительно ведёт
  внутрь папки назначения — в том числе если внутри неё подложили символическую
  ссылку наружу;
* исходная папка никогда не изменяется, и программа отказывается работать, если
  источник и назначение совпадают или вложены друг в друга;
* существующие файлы не перезаписываются без `--overwrite`;
* файлы копируются во временный файл и переименовываются на место, поэтому
  прерывание не оставляет обрезанных файлов.

## Формат файла структуры

Версия 2 — объект JSON с заголовком и списком записей:

```json
{
  "format": "dp_backup_structure",
  "version": 2,
  "created_at": "2025-05-01T12:00:00+00:00",
  "source_root": "/mnt/ssd/Данные",
  "hash_mode": "full",
  "items": [
    { "path": "Фото", "kind": "directory", "mtime": 1714000000.0 },
    { "path": "Фото/закат.jpg", "kind": "file", "size": 2048576,
      "digest": "9f86d0…", "mtime": 1714000000.0 },
    { "path": "Ссылка", "kind": "symlink", "target": "Фото", "mtime": 1714000000.0 }
  ]
}
```

Файлы структуры версии 1 (простой список с `original_relative_path`,
`type`, `size_bytes`) читаются как есть — перезаписывать их не нужно. Хешей в
них нет, поэтому сопоставление пойдёт с яруса 2.

## Ограничения

* `--hash partial` не видит различий в середине больших файлов. Если это важно,
  используйте `--hash full` (по умолчанию).
* Если файл переименован при восстановлении **и** его размер совпадает с
  другими, без хешей его опознать нечем — он попадёт в отчёт как неоднозначный.
* Права доступа копируются с файлов-источников, а не из структуры; владелец и
  ACL не сохраняются.
* Сокеты, FIFO и файлы устройств пропускаются — в них нечего восстанавливать.
* Символические ссылки записываются как ссылки и воссоздаются как есть. В
  Windows для этого нужны соответствующие привилегии; если их нет, ссылка
  попадёт в отчёт как неудачная, а остальное восстановится.

## Что изменилось по сравнению с версией 1.x

* Сопоставление по содержимому вместо «только по размеру» — файлы больше не
  меняются местами.
* При неоднозначности программа отказывается гадать и пишет об этом в отчёт.
* Дубликаты в исходном дереве восстанавливаются полностью.
* Закрыт выход за пределы папки назначения через путь из файла структуры.
* Повреждённый файл структуры больше не роняет программу с трассировкой.
* Лог ротируется (раньше на 3000 файлов одного размера он вырастал до 85 МБ).
* Поиск кандидатов стал линейным вместо квадратичного.
* Восстанавливаются даты изменения и символические ссылки.
* Появились режим предпросмотра, отчёты, полноценный CLI и коды возврата.
* Ядро отделено от Tkinter, поэтому работает и без графической оболочки.

списка файлов. И вот на такой случай нужна эта прога. Нужно просто сканировать
структуру каталогов и файлов и затем при повреждении фс или носителя через этот
скрипт можно восстановить оригинальную структуру и раскидать файлы туда, где
они были изначально.
